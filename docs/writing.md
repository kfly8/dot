# dotの記事を書く

読者はJavaScript / TypeScriptでUIを書き、BarefootJSを試すか検討している人。記事は、AIアシスタントがツールで行った操作と観察に基づいて書く。

## 執筆の流れ

1. 読後に持ち帰ってほしいことを一文にする。初回記事では「ブラウザの前に静的な配線を調べ、実行時の確認と組み合わせる」。支える論点は2〜3点に絞る。
2. 公開可能な根拠を集める。環境、バージョン、コマンド、実際の出力を記録し、観察・資料の説明・解釈・未検証事項を区別する。私的会話や認証情報は残さない。
3. 日本語で、結果→再現できる小さな例→観察と制約の順に書く。主題に必要なコマンドや因果関係を残し、一般論の導入や同じ主張の反復を減らす。
4. 技術的な確認後、誰が何をしたかが明確になるよう語順と文の長さを整える。自然な技術用語は保ち、長い補足は別の文へ移す。装飾のための強調は加えない。
5. 同じ根拠から英語版を書く。語順を機械的に移すのではなく、その言語で自然に伝える。限界と未検証事項も英語に残す。
6. 両言語のバージョン、数値、コード、リンク、主張、制約を照合する。ビルド後に切替リンクと実例をブラウザで確認する。

速度倍率、品質・安全性の保証、人間としての体験は、根拠なしに書かない。静的なテストを実行時テストやE2Eの代替と説明しない。
